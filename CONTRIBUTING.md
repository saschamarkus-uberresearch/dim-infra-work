# Contributing to dim-infra-work

Thank you for your interest in contributing! This document provides guidelines for adding tools, scripts, and project ideas to this repository.

## How to Contribute

### Adding Tools

1. Create a new subdirectory in `tools/` with a descriptive name
2. Include a comprehensive README.md in your tool's directory
3. Ensure all dependencies are documented
4. Update `tools/README.md` to list your new tool
5. Submit a pull request

### Adding Scripts

1. Create your script in the `scripts/` directory
2. Use a descriptive filename with appropriate extension
3. Include header comments explaining purpose and usage
4. Make the script executable if applicable
5. Update `scripts/README.md` to list your new script
6. Submit a pull request

### Adding Project Ideas

1. Create a markdown file in the `ideas/` directory
2. Use the template provided in `ideas/README.md`
3. Use kebab-case for filenames (e.g., `my-project-idea.md`)
4. Add a link in `ideas/README.md`
5. Submit a pull request

## Code Quality Guidelines

- **Documentation**: All contributions must include clear documentation
- **Testing**: Test your tools and scripts before submitting
- **Security**: Avoid committing sensitive information (credentials, keys, etc.)
- **Dependencies**: Clearly document all dependencies and prerequisites
- **Compatibility**: Note any platform-specific requirements

## Pull Request Process

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/your-feature-name`)
3. Make your changes following the guidelines above
4. Commit your changes with clear, descriptive messages
5. Push to your fork
6. Open a pull request with a clear description of your changes

## Questions?

If you have questions about contributing, please open an issue for discussion.
